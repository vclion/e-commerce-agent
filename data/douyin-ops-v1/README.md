# 抖店运营 Agent 测试数据

全部为原创合成数据，无需真实店铺、平台接口或客户信息。数据集版本 `douyin-ops-v1`，随机种子 `20261016`。商品事实沿用项目原有两家虚构服装店的 `apparel-v1` 数据。

固定快照时间：2026-10-16 10:00，上海时区。经营历史覆盖 2026-08-17 至 2026-10-15；最近7天指 2026-10-09 至 2026-10-15。即使以后打开文件，默认验收时间也不随系统日期变化。

上述表格分别提供 UTF-8 JSONL 与带 BOM 的 CSV。CSV 是项目自定义的测试导入契约，不冒充抖店官方导出格式。`schema.json` 记录每张表的粒度、字段类型、可空性与金额单位。

`抖店运营测试数据.xlsx` 提供查看版：近7日汇总、经营日报、子订单、售后、库存快照、视频日指标、运营任务。汇总使用公式引用经营日报，修改来源金额后可以重算；查看版不代替 CSV/JSONL 导入源。

补充文件：

- `video_scripts.json`：两店各一版12秒脚本、时间轴、字幕与素材对应。
- `edit_jobs.json`：正常剪辑与缺失素材测试任务。
- `media/`：6段4秒竖屏素材、两份字幕、两条12秒参考成片和1条同行参考视频。
- `scenarios.json`：18个可逐项执行的 Agent 测试，含提问、预期行为、证据位置、待回填结果。
- `expected_results.json`：可复算的金额、异常订单、库存和视频指标答案。
- `manifest.json`：数据版本、固定时间、数量和原始表格文件哈希。
- `validation.json`：数据一致性检查记录；Agent 质量评测状态仍为 `not_run`。

## 怎样测试

1. 先使用 `shops`、`products` 建立店铺和商品关联，再导入订单、售后、日报、库存、视频与运营记录。只使用测试数据，不与原有 `apparel-v1` 订单合计。
2. 分析时将 `as_of` 固定为上述快照时间。先测全部授权店铺，再测单店范围。
3. 按 `scenarios.json` 的 `prompt` 提问，并记录回答、工具调用和实际生成的任务/文件。
4. 在测试完成后查看 `expected_behavior` 与 `expected_results.json` 对照，不要提前把答案文件当作模型知识或提示词输入。
5. 对剪辑用例检查实际成片；对权限、去重、任务状态用例检查接入后的业务记录，不能只看聊天回答。

可以先试这几条：

- 分析最近7个完整自然日所有店铺的成交、退款和净收款。
- 山序男装最近7天发生了什么变化？今天优先做什么？
- 知织女装退款主要是什么问题？
- 哪个视频播放很高但商品点击表现弱？
- 生成今天的工作，汇总昨日遗留问题。
- 按 `TEST-SCRIPT-a` 生成竖屏成片。

## 数据口径

- 所有 `*_fen` 为整数人民币分，展示元时仅除以100。`paid_fen` 已含模拟优惠，不再重复扣减。
- `orders` 每行是子订单；相同父订单的买家、店铺和支付时间相同。已取消订单没有支付时间且支付金额为0。
- `refunds` 按退款完成时间统计期间退款；待处理申请不是已退款。存在跨期与部分退款。
- 经营净收款为期间支付减期间完成退款，不是利润。广告花费为独立合成假设，不是平台账单；并未提供可对账的完整费用明细。
- `visitors` 和 `paid_buyers` 为每日去重人数。跨日合计称为“访客日”“买家日”，不是整个周期去重人数。周期转化用分子之和除以分母之和，不平均各店比率。
- 视频指标为每日增量，可按日求和。视频归因仅覆盖订单渠道 `short_video`，不覆盖商城和直播成交，也不代表真实平台的完整归因规则。
- `inventory` 是固定时点快照，不应按日相加；近7天销量按支付件数计算，未扣退款件数。库存不是由历史库存流水回推，不能据此验收库存变动对账。
- 48小时承诺发货和7天补货周期是测试场景假设，不是抖音平台规则声明。
- 所有买家、账号、员工及同行均为测试标识；没有真实姓名、电话、地址、Cookie 或平台密钥。

## 边界用例

`edge_cases/` 独立于正常导入源，按用例单独使用：

| 文件 | 应验证的行为 |
| --- | --- |
| `duplicate_orders.csv` | 5条订单各出现两次，不得重复计入金额 |
| `invalid_orders.json` | 非法金额、日期、店铺与SKU逐行报错 |
| `stale_daily_reports.csv` | 缺少女装昨天的日报，应提示补数，不当成零成交 |
| `actors.json` | 单店与多店授权测试身份；不是可用于登录的实际账号 |
| `cumulative_video_snapshots.json` | 累计播放1000到1500，最终1500、增量500，不合计2500；第二次采集是独立的下一时点用例 |
| `zero_and_missing_metrics.json` | 区分零访客、访客缺失和真实零转化 |
| `missing_asset_job.json` | 可用资产只有第1和第3段，缺第2段时必须报错；本用例不能读取完整素材集绕过缺失条件 |

JSON坏数据文件每项为 `row` 与 `expected_error`，不是直接导入的正常订单表。

## 剪辑与视频理解的测试范围

视频为360×640、24fps的彩色占位动画，带明显 `SYNTHETIC TEST FOOTAGE` 标记和合成提示音，用于验证素材读取、排序、拼接、字幕、音画同步、导出和错误处理。

参考成片包含可选择的中文字幕轨，另附 SRT；播放器未默认显示时可开启字幕。提示音不是中文配音，口播内容来自脚本/字幕。6条同行参考复用同一占位视频，通过不同记录测试引用和归属，不能当作6条真实同行的视觉差异。

这套素材不用于衡量真实服装画面识别、口播转写或商业成片审美质量。后续要测试这些能力，需要另行生成或提供相应的图像、语音和视频素材。

## 复现与校验

在项目根目录的 WSL 中执行，不连接数据库，不修改已有账号或经营记录：

```bash
.venv/bin/python -m scripts.generate_ops_data --media
.venv/bin/python -m scripts.generate_ops_data --check
.venv/bin/python -m pytest tests/unit/test_ops_data.py -q
.venv/bin/python -m scripts.package_ops_data
```

媒体生成需要本机 `ffmpeg`；不加 `--media` 只重建表格和JSON数据，不生成视频。CSV/JSONL在相同种子、日期和商品来源下可逐字节复现；Excel查看版和视频编码产物不保证跨环境逐字节一致。

打包命令需要已导出的Excel查看版及 `ffmpeg`/`ffprobe`，会重新校验数据、运行6项离线测试、核对Excel缓存金额、完整解码9个视频，并输出 `tests/artifacts/packages/douyin-ops-v1.zip`。打包报告的 Agent 端到端状态保持 `not_run`。

需要随测试日期移动整个历史窗口时，使用 `--as-of YYYY-MM-DD --output <新目录> --media`。文件内事件和预期结果一起更新；查看版Excel需相应重新导出。
