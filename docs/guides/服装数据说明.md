# 服装演示数据 v1

> 数据仍供当前运营工作台使用；下文早期“导购”场景现作为运营商品筛选和文案依据。消费者、商家入口已移除，当前验收见《运营单入口验收.md》。

当前数据版本为 `apparel-v1`，生成种子为 `20261016`。生成时以当日上海零点为基准，向前覆盖90个完整自然日；基准时间固定保存在 `manifests` 中。重复启动不刷新日期或重新造数。

## 数据来源与真实性

商品名称、面料成分、尺码表、价格、库存、订单、渠道、质量与供货观察、退款原因和竞品价格均由本项目原创生成。没有采集真实消费者或店铺记录，也不代表真实品牌销量、市场价格或质量结论。

网上参考了 [Fashionpedia 官方项目](https://github.com/cvdfoundation/fashionpedia) 中将服装品类与细分属性分开描述的结构。它是服装视觉与属性数据集，不是可直接支撑本商城订单、采购成本和退款的经营数据库。本项目未导入它的图片、标注或样本，没有将合成经营事件冒充公开真实交易。

页面服装图为项目自绘SVG款式示意，按照品类与颜色变化，不是实拍商品图，不作为面料肌理、颜色精度或工艺效果的依据。

## 可以演示的场景

1. 男装导购：“300元以内、L码、含棉、通勤衬衫”。`MEN-001-01-L` 云白L码库存为0，不会出现在默认有货结果；同款雾蓝L码仍可匹配。
2. 女装导购：“400元以内、M码、通勤连衣裙”。只返回知织女装库存，不能把男装库存混入推荐。
3. 尺码咨询：核对具体SKU的成衣胸腰臀围、长度与偏好。只给身高体重时追问，不保证合身；混纺成分不能描述成纯羊毛或纯棉。
4. 季节差异：夏季短裤库存较高、近期需求较低；秋冬针织与外套近期订单权重增加。这是生成设定，不是从真实天气推断的因果事实。
5. 经营分析：最近7个完整自然日，男装成交98,606.00元、221单，女装成交163,201.00元、367单；分别环比18.27%和53.32%。基准窗口为2026-10-08至2026-10-14，后续查看日期变化时应以接口即时窗口为准。
6. 售后结构：同一窗口男装退款3,501.00元、女装退款13,115.00元。退款原因可以展开查看，女装尺码和版型相关退款较多。退款按发生时间统计，不能把“本期退款额/本期成交额”称为同一批订单退货率。

库存是独立的当前快照，不通过订单倒推出完整库存流水；尚未生成进货、盘点、预留和出库流水。历史订单含购买时的规格快照，不能用今天的商品资料改写过去订单。

## 文件与复现

`data/apparel-v1/` 提供：

- `styles.json`：80个原创款式定义。
- `products.jsonl`：800个SKU，含款号、成分、围度、价格分、成本分和库存。
- `orders.jsonl`：5,521笔演示订单，含规格快照、渠道和退款原因。
- `competitors.jsonl`：2,400条同规格虚构快照，来源统一为 `demo://apparel-v1/...`。
- `manifest.json`：版本、种子、日期、店铺定位与记录数。

JSONL为UTF-8，每行一个JSON对象。`*_fen` 均为人民币整数分，`cm` 为成衣尺寸厘米。竞品与采购成本用于授权运营分析；当前仅开放运营接口。

```bash
cd ~/e-commerce-agent
.venv/bin/python -m commerce.seed
.venv/bin/python -m scripts.export_apparel
```

首次生成创建当前服装数据；再次执行不会覆盖现有数据或密码。需要复现到另一环境时，应在空业务库中初始化；种子外还需相同基准日期才会得到完全相同的订单时间。

原300个数码SKU标为归档，原3,002笔订单保留但排除在当前订单列表、经营统计和选品需求之外。迁移前完整业务库备份在本机私有 `.runtime/backups/apparel-migration/business-before.sql`；管理员、模型凭据和现有登录账号均保留。
