# 导入与文案增强说明与验收

2026-10-18。对应 GitHub 调研建议的首批两项：文案事实检查与定向改写、报表字段映射与 Excel 导入。

## 使用入口

在 [运营工作台](http://localhost:8000) 刷新页面。

### 文案检查与定向改写

1. 进入“短视频运营”，在脚本卡片点击“检查文案事实”。新建或保存的脚本会自动附上规则检查结果。
2. 每条结果标记标题或分镜位置，显示原表述、对应商品资料和修改建议。检查覆盖价格、面料成分及含量、尺码、促销和常见性能承诺。
3. 编辑脚本时，可勾选“锁定本段字幕，定向改写时保留”，然后保存。锁定段仍显示待核对表述，但不参与自动改写。
4. 点击“定向改写一轮”，通过现有 `video-script` Dify Workflow 调用 DeepSeek。只采用有问题且未锁定的字幕；标题只在有问题时改写。正常字幕、分镜顺序、素材 ID 和截取时间由后端保留。
5. 查看改写差异与剩余待核对项，点击“采用并保存新版本”，或放弃改写。生成候选不会覆盖原脚本；采用时继续检查版本，防止覆盖别人的修改。

价格和尺码基于当前具体 SKU；其他尺码需要另查。面料检查识别纯成分、百分比和常见同义词；规则没有覆盖的描述仍需人工核对，不能把“没有命中”理解为全部事实已验证。现有商品数据没有完整活动及性能验证字段，因此相关承诺会提示核实。未增加模型质量总分或完整平台规则认证。

模型调用失败时显示失败原因，原脚本保持原版本。检查本身在本地执行，不依赖模型服务。

### Excel 与字段映射

1. 进入“数据导入”，选择报表类型并上传 CSV、JSON、JSONL 或 `.xlsx`。Excel 可选择工作表；首行为字段表头。
2. 中文表头和 Excel 默认进入映射模式。系统给出候选匹配，运营逐项确认源列；歧义字段需要手动选择。标准 CSV/JSON/JSONL 可继续沿用原契约。
3. 选择本地授权店铺。源列有店铺 ID 时，必须与所选本地店铺一致；如果平台店铺编码与本地编码不同，需取消该源列映射，明确绑定本地店铺。
4. 每个金额字段确认元或分，内部统一保存为分；不静默四舍五入。无时区的时间按所选“上海”或“UTC”解释，已有时区的时间保持原值。
5. 缺失字段可补固定值；可空字段留空保持未知，金额不会自动补零。未提供来源标识时使用 `manual-import-v1`，未提供测试标记时默认为非测试数据；测试报表应明确标记。
6. 订单状态、渠道、退款状态及指标口径支持常用中文值转换；其他值可在相应字段下填写 `原始值=标准值`，一行一项。无法识别的值报出具体行号。
7. 可给映射起名并保存，下次在同一账号和授权店铺内复用。调整映射或单位会清除旧预览，必须重新校验。
8. 点击“校验报表”，查看转换后的前五行和逐行错误；全部通过后再“确认导入”。沿用原有批次去重、引用关系校验及事务提交，有错误时不部分入库。

Excel 最大16MB、解压后64MB，最多25,000个数据行、150列。旧 `.xls` 需另存为 `.xlsx`。公式与错误单元格需要先转换为有效值。长订单号请以文本保存；数值型长 ID 会被拒绝，以免接收 Excel 已经损失精度的数据。

当前提供通用映射和常用别名，验收使用合成表头；具体真实平台导出模板仍需以实际样例核验，不把合成示例称为官方已适配模板。

## 实现位置

| 文件 | 职责 |
| --- | --- |
| `backend/commerce/ops_content.py` | 商品事实的确定性检查 |
| `backend/commerce/ops_media.py` | 自动检查、按版本检查、单轮改写候选及锁定保护 |
| `backend/commerce/ops_imports.py` | Excel读取、字段建议、格式转换、映射模板 |
| `backend/commerce/ops_data.py` | 复用原校验、去重、批次与事务，保留源行号 |
| `backend/commerce/ops_schemas.py`、`ops_api.py` | 输入约束及API |
| `frontend/src/ReportImporter.vue` | 文件、工作表、映射与校验预览 |
| `frontend/src/ScriptReview.vue`、`OpsWorkspace.vue` | 检查结果、锁定编辑和改写差异 |

新增 `GET/POST /api/ops/import-mappings`、`POST /api/ops/imports/inspect`、`POST /api/ops/scripts/{id}/review` 和 `/rewrite`。原导入预览和脚本保存接口向后兼容。映射模板使用现有 `OpsRecord` 按账号与店铺隔离，未增加数据库表或修改既有演示记录。
