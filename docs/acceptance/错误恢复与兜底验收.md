# 错误恢复与兜底验收

日期：2026-10-25。

## 实施范围

在现有聊天和工具入口增加恢复保护，保留原有业务计算、Dify DSL、平台同步与剪辑规则。具体行为见[错误恢复与兜底](../guides/错误恢复与兜底.md)。

- 同账号请求标识去重和已有结果重放。
- 按账号、店铺、栏目、数据来源及原指令核对恢复请求。
- 同轮同参数写工具的持久化执行记录、并发去重、成功结果缓存。
- 提交前失败回滚；提交后异常保留待核对状态，不直接重放写操作。
- 根据业务执行状态决定安全重试或核对已有结果，包括原消息的后续重试链。
- 流式正文检查点、过期运行回收、旧工具令牌失效。
- 新增恢复提示和“核对执行结果”入口。
- 增量表和列迁移；删除原运行时只级联清理新增执行记录，不删除已产生的业务数据。

## 故障注入覆盖

- 报告写入成功后模拟模型连接失败，点击核对后仍只有一份报告，模型没有再次调用。
- 提交事务后模拟处理器异常，执行记录保持 `uncertain`，相同写请求不重复执行。
- 提交前异常，业务修改回滚，确认没有已提交或结果不确定的写入后可重试。
- 两个并发相同写请求仅允许一个进入业务处理器。
- 过期运行保留已有正文并使工具令牌失效，正常运行不被回收。
- 原消息重试成功或产生写入后，再点击原消息不会绕过后续记录重复执行。
- 刷新页面后恢复运行状态、执行回执和核对入口。
