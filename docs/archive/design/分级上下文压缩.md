# 分级上下文压缩

> 本文保留 2026-10-21 的分级方案记录。2026-10-22 已改用[索引式上下文管理](../../design/索引式上下文管理.md)：默认最近 3 轮完整原文、简短任务线索和少量活跃索引，旧段按需回查。下文的 6/12 轮装载与全文摘要注入不再是当前行为。

实现日期：2026-10-21。后端统一编排，Dify 通过固定 bootstrap 读取本轮快照，Agent 自带历史保持关闭。

| 层级 | 默认范围 | 处理方式 |
| --- | --- | --- |
| 近期原文 | 最近 6 轮 | 优先完整保留用户问题、助手回答、状态、实际操作结果 |
| 轻度整理 | 之前 12 轮 | 去除助手回答中的额外空白与完全重复段落，不改写用户问题、数字和操作结果 |
| 分段摘要 | 更早的对话，每 8 轮一段 | 根据本段原文独立生成，关联来源 ID、起止轮次、主题与关键原文 |
| 主题概要 | 同一分段的更短表达 | 与摘要同时直接根据原文生成，空间不足时使用，不反复摘要旧摘要 |

预算充足时直接装载全部原文。空间紧张时，优先保留关键用户约束、决定和数字，装载最新消息，再按问题相关性选择历史分段。相同关键句去重，避免重复约定挤掉早期唯一金额或编号。

单条近期助手回答装不下时，先保留用户问题和实际操作结果，助手正文提供回查入口，不静默截成前 2500 字。未装入的原文仍保存在数据库。快照记录遗漏轮数，并提示模型不能假设掌握全部历史。

关键句是带轮次的用户原话，不自动变成永久事实，后轮明确修正优先。助手建议与真实完成分开。关键句抽取采用规则，不保证穷尽所有自然语言约束，细节不足时仍须回查。

## 预算和配置

```dotenv
MEMORY_CONTEXT_TOKENS=32000
MEMORY_MODEL_CONTEXT_TOKENS=65536
MEMORY_RESERVED_TOKENS=16384
MEMORY_RECENT_TURNS=6
MEMORY_LIGHT_TURNS=12
MEMORY_SEGMENT_TURNS=8
```

上下文预算为 `min(上下文额度, 模型额度 - 预留额度 - 当前问题计数)`。预留额度用于固定指令、工具与结果、模型输出。模型额度是可配置的本地保守上限，并非自动识别的供应商模型容量；更换模型需核对配置。

未安装模型专用 tokenizer：以 **UTF-8 字节数作为面向字节分词器的保守上界**，中文尤其保守，不等于精确 token 数，不需要下载模型或词表。旧 `MEMORY_CONTEXT_CHARS` 为兼容保留，不再用于分级裁剪。长期记忆和关键句分别最多使用约五分之一的额度，其余用于对话与分段。

预算内不能保证无限历史同时出现，通过原文回查补足。当前每轮仍读取本会话的有效历史，尚未进行万轮会话的性能优化或压测。

## 后台与存储

- `memory_context_segments` 保存独立摘要、概要、关键用户原文、来源轮次及会话 epoch，编号迁移 4 增加该表，不改写既有聊天正文。
- `extract` 只抽取本轮记忆候选与真实事件；`compress` 独立处理超过近期窗口的旧对话。
- 压缩输入只有本段原文，`prior_summary` 为空。摘要和概要必须同时存在，缺失则重试，不使用旧摘要补造。
- 写回前检查租约、记忆 epoch、会话 epoch 和来源集合，防止并发重复、遗忘后写回。完成后可继续排队下一段，消化积压。
- 单条超大原文留待回查，不阻塞后续正常对话分段。
- 旧 `summary`、`through_seq` 为兼容保留，不再自动注入；新分段从原始记录重新生成。

## 原文回查

```json
{"operation":"history_read","arguments":{"query":"活动素材"}}
{"operation":"history_read","arguments":{"run_id":"来源ID","field":"assistant","offset":0,"length":1200}}
```

不传 run_id 时，按关键词匹配当前会话原文，返回最多三个来源入口。指定 ID 后可读 `user`、`assistant`、`effects`。偏移按字符计算，用 `has_more` 和 `next_offset` 续读；返回体有大小限制，回查本身不触发模型或 Embedding 请求。

只允许当前用户、店铺、栏目、数据环境、本地会话及当前轮次之前的有效原文。其他会话、已排除来源和临时对话不能回查。读取来源补记到本轮依赖中，仍受每轮 8 次工具调用限制。

纠正、遗忘与撤权继续使旧快照失效、清理分段、推进 epoch 并重置上游会话。遗忘递归排除旧回答依赖，已排除原文不能经回查重新进入模型。原始聊天保留策略不变，退出模型上下文不等于 Dify、日志或备份的物理删除。
