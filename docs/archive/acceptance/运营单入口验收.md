# 运营单入口实现与验收

日期：2026-10-16。当前业务仅服务运营人员，取代原消费者、商家、运营三端入口。

## 实际变更

| 范围 | 当前行为 |
| --- | --- |
| 登录 | 仅接受运营角色；默认账号 `operator` 映射到 `operator-a`，兼容既有运营账号 |
| 历史身份 | 消费者、商家和测试买家无法登录，旧身份持有未过期会话/工具令牌也被拒绝 |
| 工作台 | 经营概览、商品资料、店铺订单、选品研究、文案与报告、运行记录 |
| 店铺权限 | 默认全部授权店铺；可筛单店，逐次校验 membership，撤销权限后旧工具上下文也不可继续查询 |
| 订单与售后 | 运营按授权店铺只读查看，订单不再以登录运营账号充当买家过滤；不返回买家账号字段 |
| 内容保存 | 运营可保存营销文案或经营报告；草稿按所有者和店铺范围读取，不混入旧上架资料或消费者工单 |
| 专属流程移除 | 商品新增、编辑与上架，消费者售后准备/提交及动作确认接口、页面、Schema和业务函数已移除 |
| 助手工具 | 保留商品、对比、订单、售后记录、经营分析、选品、竞品、知识检索和澄清；移除售后准备与旧售后规则操作 |
| Dify | 1个运营Chatflow与4个Workflow：商品筛选、营销文案、选品研究、经营分析 |
| 旧Dify应用 | 消费者、商家、售后准备、商品草稿应用关闭API和站点，保留工作空间历史与本机回退备份 |
| 知识 | 30份资料更新为v2，明确运营范围、只读售后和草稿边界，保留原文档ID以兼容历史引用 |

现有买家记录和旧业务表保留，用于订单外键和历史记录；保留不代表这些身份仍可进入系统。运行数据库的既有商品、订单、模型配置与运营历史未被重新生成。

| 经营对话 | 真实DeepSeek调用成功，审计有 `tool.analytics`，金额与订单数和API一致 | `tests/artifacts/reports/live-model-report.json` |
| 对话恢复 | 5项浏览器检查通过，2次真实模型调用；覆盖刷新恢复、原会话追问与不同运营账号隔离 | `tests/artifacts/reports/chat-history-report.json` |

浏览器基础验收中的模型输出使用模拟SSE，仅内容保存调用真实业务接口；真实模型能力由另外的经营对话、营销Workflow与对话恢复验收覆盖。上述均为冒烟与回归验证，不是批量模型效果、性能或成本评测。

后端测试仍有一条已有的FastAPI/Starlette测试客户端弃用提示，不影响此次结果。

## 本机复验

```bash
.venv/bin/python -m pytest -q
npm --prefix frontend run build
.venv/bin/python -m tests.scripts.browser_smoke
.venv/bin/python -m tests.scripts.smoke_dify
.venv/bin/python -m tests.scripts.live_smoke --role operator
.venv/bin/python -m tests.scripts.browser_chat_smoke
.venv/bin/python -m tests.scripts.verify_operator
.venv/bin/python -m tests.scripts.verify_delivery
```

`live_smoke`、`browser_chat_smoke` 与 `verify_operator` 会调用已配置的真实模型，其余不需要模型生成。浏览器回归只清理本轮创建的唯一草稿；对话恢复测试使用临时运营账号并在结束后清理。
