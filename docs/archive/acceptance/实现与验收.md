## 固定版本

- Python 3.12.13，Node v24.22.0。
- Dify 1.17.1，源码提交 `8387590ace4a094de812b7847fc6a4c3a27cd52b`，DSL 0.7.0。
- 官方 DeepSeek 插件0.0.24，官方 Agent 策略插件0.0.50；包标识与摘要在 `dify/plugins.lock.json`。
- PostgreSQL16。业务数据与Dify内部数据分开。
- Python 和前端完整依赖分别锁定在根目录 `uv.lock` 与 `frontend/package-lock.json`。

## 当前数据

山序男装与知织女装两家店铺、80个SPU分组、800个SKU、5,521笔服装订单、2,400条合成竞品快照，以及20份公开资料和10份内部资料。服装版本为apparel-v1，种子随机数固定为20261016，基准日期保存在数据库`manifests`表。

选品的供货与质量观察是合成聚合数据，未宣称从真实业务事件推导；商城不会因为上架新品自动增加销售记录。竞品导入只保存用户提供的快照，不自动访问外部URL或核验来源真实性。

旧版300个数码SKU已归档，3,002笔旧订单保留但不参与当前目录、订单列表和经营指标；本地迁移前备份位于私有`.runtime/backups/apparel-migration/`。服装数据说明与实际两店对照见`服装数据说明.md`。

## Dify应用组织

- 消费者Chatflow：抽参 → JSON校验 → 授权业务工具 → 公开知识检索 → 有依据回复。
- 商家Chatflow：受限Agent，可查只读数据并调用商品/营销草稿Workflow。
- 运营Chatflow：受限Agent，可调用选品研究和经营分析Workflow。
- 商品匹配与售后准备Workflow提供独立、可复用的确定性工具入口。
- Agent本身最多5轮；嵌套Workflow共用后端请求上下文，业务工具调用合计最多8次。

确认提交走工作台与业务API，不依赖模型判断“用户已确认”。售后只创建申请，退款状态由后续业务流程负责。

2. 已完成三端真实对话冒烟验证；后续建立调优集/冻结集并记录失败案例，不能提前填报效果数字。

7. Redis、迁移工具、日志/过期凭据清理任务和压测尚未作为生产能力交付；当前面向本机演示。

## 对话历史修复（2026-10-15）

原有记录已保存于PostgreSQL，但前端仅有一个手动恢复图标，未自动加载，且运行记录未保存会话关联。现新增明确的历史对话入口、会话切换、消息分页与自动恢复；新消息保存Dify会话ID和资料引用，刷新后可继续相同会话。旧20条记录全部保留，其中17条依据用户归属与工具上下文恢复了会话关联，其余单独展示。

验证见`tests/artifacts/reports/chat-history-report.json`；后端新增会话分页、跨用户隔离、旧记录保留及流式保存/追问测试。
