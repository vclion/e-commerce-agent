# 索引式上下文管理

更新：2026-10-22。替代先前“6 轮原文 + 12 轮整理 + 历史摘要直接注入”的装载方式；既有原文、后台分段、长期记忆、权限与遗忘机制继续使用。

## 默认发送内容

1. 最近 3 轮完整的用户问题、助手回答、状态和实际操作结果，按轮次正序排列。
2. 简短的用户约束和未完成任务线索，最多 3 条，并保留原话和来源。目标从近期原文和索引主题中理解，不把助手建议提升为已确认目标。
3. 最多 3 条活跃摘要索引：索引 ID、主题、一句话提示、关键实体、起止轮次。完整摘要、概要全文与更早原文不主动发送。
4. 少量必要的有效长期约定，最多 3 条，受独立小预算限制。

即使上下文预算有剩余，也不追加旧原文或完整摘要。默认路径仅读取近期助手正文和历史来源元数据，不扫描所有历史助手正文。最近 3 轮自身超出预算时可触发[响应式压缩兜底](响应式上下文压缩.md)，临时摘要较早轮次并保留最新一轮原文；仍装不下时明确报错，不静默截断。

任务线索来自可追溯的用户原文，不保证穷尽自然语言中的全部状态。明确未完成的任务和仍有效约束获得保护；匹配到后轮明确完成的任务会解除保护。复杂纠正和状态仍需回查原文或业务工具。

## 活跃与冷索引

- 每条索引记录最近实际使用时间、使用轮次和使用次数。
- 普通索引超过 24 轮未用，或超过 7 天未用，退出默认上下文。
- 使用频次会有限延长热期：最多增加 10 轮、5 天，不会永久保温。
- 有明确未完成任务或约束的索引优先保留；仍受默认索引数量与提示词预算限制。
- 仅展示在提示词中、仅出现在搜索结果中，都不刷新使用时间。成功按索引定位原文，或读取其来源原文后才重新激活。
- 同一轮多次读取同一索引只计一次使用。冷索引和原文保留在数据库，不因变冷而删除。

后台继续按独立原文分段生成摘要和概要，用于索引与历史恢复。最近 3 轮不纳入旧段；更早记录积累到分段大小后后台整理。尚未建立索引的历史仍支持原文搜索。

## 按需读取

```json
{"operation":"history_read","arguments":{"query":"旧活动主题"}}
{"operation":"history_read","arguments":{"index_id":"索引ID","limit":3}}
{"operation":"history_read","arguments":{"index_id":"索引ID","run_id":"来源ID","field":"assistant","offset":0,"length":1200}}
```

搜索覆盖当前会话的活跃索引、冷索引以及未建索引原文；没有索引不等于没有历史。按 index_id 返回该段原文轮次入口，使用 `after_turn` / `next_after_turn` 翻页。选择相关 run_id 后读取 user、assistant 或 effects，正文使用 `offset` / `next_offset` 分页。只补充相关轮次及必要字段，不自动把整个历史会话载入。

工具返回有大小限制，最多仍受本轮 8 次工具调用总上限约束。不得根据一页原文推断未读部分。读取来源追加到快照依赖中。

## 配置

记忆管理页面分别提供“长期记忆自动写入”和“上下文索引整理”，两者默认开启，独立保存：

- `auto_write` 只控制自动提取长期记忆候选、经验候选和业务事件记忆；模型的非明确保存提议同样受控。不影响用户手动保存或明确要求“记住”，也不控制已有记忆读取。业务审计记录始终独立保留。
- `context_index_enabled` 只控制后台生成对话摘要索引；不影响最近 3 轮原文加载、已有索引的使用和搜索、冷热判断或响应式临时压缩。
- 关闭开关停止对应任务，不删除已有记忆、索引或原文。排队及正在执行的对应任务会失效，写入前再次校验；重新开启不恢复已失效任务，后续新对话触发整理。索引任务会按原文分段补齐历史，长期记忆不自动补提取停用期间的旧对话。
- `read_enabled` 独立控制回答时读取长期记忆；切换时让旧上下文快照失效，但保留历史索引及后台整理任务。`reflection_enabled` 是自动写入下的经验候选子选项。
- 设置 API 支持部分 PATCH；旧客户端不传 `context_index_enabled` 时保留其已有值。内容遗忘、纠正和撤权仍走原有来源失效流程。

迁移 6 增加独立索引开关和读取策略版本，保留现有自动写入偏好，新索引开关默认为开启。部署级 `MEMORY_ENABLED`、`MEMORY_WORKER_ENABLED` 继续作为记忆后台服务总开关。

```dotenv
MEMORY_RECENT_TURNS=3
MEMORY_LIGHT_TURNS=0
MEMORY_SEGMENT_TURNS=8
MEMORY_INDEX_ACTIVE_LIMIT=3
MEMORY_INDEX_IDLE_TURNS=24
MEMORY_INDEX_IDLE_DAYS=7
MEMORY_INDEX_CONTEXT_TOKENS=2400
MEMORY_TASK_STATE_TOKENS=1200
MEMORY_LONG_CONTEXT_TOKENS=2400
```

总额度仍由 `MEMORY_CONTEXT_TOKENS`、`MEMORY_MODEL_CONTEXT_TOKENS`、`MEMORY_RESERVED_TOKENS` 控制；原文之外各模块有独立小预算，并非预算够就填满。继续使用 UTF-8 字节保守上界，不是模型精确 token 计数，不下载 tokenizer、模型或依赖。`MEMORY_LIGHT_TURNS` 仅为旧配置兼容保留，已不参与默认装载及后台保留窗口。

编号迁移 5 为既有分段表增加实体和使用元数据，不删除已有记录。Dify 自带历史注入保持关闭，bootstrap 读取后端固定快照。遗忘、纠正、撤权、会话/店铺/栏目/环境校验继续作用于索引、搜索和原文读取；临时对话不读取索引或历史。
