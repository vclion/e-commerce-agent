# 电商运营 Agent 业务方案

日期：2026-10-16。报表导入、每日SOP执行、问题跟进、视频脚本与实际剪辑已接入并完成真实链路测试。本文保留业务目标与后续扩展方向，实际实现及限制以[运营闭环验收](../acceptance/运营闭环验收.md)为准；自动平台同步、发布、语音转写与语义画面识别仍未接入。

## 1. 产品目标

让运营人员通过一个入口管理授权店铺：每天读取数据、发现问题、安排工作、生产短视频内容、跟进执行，并在次日验证效果。

核心闭环：数据更新 → 经营诊断 → 当日任务 → 内容生产与运营执行 → 问题汇总 → 效果复盘。

用户提出的三条业务线：

1. 短视频运营：读取店铺账号短视频数据、拆解同行视频、生成文案与脚本、自动剪辑。
2. 日常店铺运营：每日运营 SOP、每日工作跟进、汇总遇到的问题。
3. 数据分析：全部授权店铺的数据汇总、对比、诊断与复盘。

用户确认：业务为抖店商品销售与快递发货，目前没有接口，首版通过报表导入数据。测试阶段所有数据由项目自行生成，不要求用户提供真实订单或报表。原表述中的“来客运营”据澄清收敛为日常店铺运营，不纳入到店团购与核销。“每日工作内容攻击”暂按“每日工作内容跟进与推进”理解。

### 1.1 抖音接入范围

首版使用报表导入，分别建立店铺和内容账号的数据归属；后续如接入 API，再单独核验权限：

| 对象 | 对应能力 | 首版接入方式 |
| --- | --- | --- |
| 抖音内容账号 | 本店短视频数据与内容运营 | 导入实际可获取的内容数据报表，并绑定账号与店铺 |
| 抖店店铺 | 商品、订单、发货及售后分析 | 导入实际可获取的经营、商品、订单与售后报表 |

官方文档核对日期：2026-10-16。

- [特定视频数据接口](https://open.douyin.com/platform/resource/docs/openapi/video-management/douyin/search-video/video-data)：`video.data` 需要申请权限和用户授权；该接口不能视为任意同行视频后台数据的访问能力。
- [抖店订单列表查询](https://op.jinritemai.com/docs/api-docs/15/1342)：需要店铺授权，具体可用能力以实际应用和店铺授权验证为准。

上述接口文档仅作为后续自动同步的依据，不是本项目已有接入能力。首版以后台实际可导出的报表建立导入契约。同行拆解优先接收用户提供的视频/字幕与参考资料，不假定能够读取同行后台完播和成交数据。

### 1.2 报表导入流程

1. 选择授权店铺、报表类型、内容账号（如适用）与统计时间范围。
2. 上传报表，预览字段映射、金额单位、时区和样例行；测试阶段使用项目自定义合成表头，后续真实接入时再匹配实际平台导出格式。
3. 校验必需字段、日期、数据归属与重复记录，返回逐行错误及处理结果。
4. 确认入库后保存批次、来源、统计口径和更新截止时间；经营诊断引用具体批次。
5. 完全相同的文件重复导入不重复计数。订单状态更新按来源标识更新，累计视频快照不按新增播放量直接相加。

报表候选包括经营概览、商品/库存、订单、售后和短视频表现，实际以用户能够导出的文件为准。订单表缺少流量时不计算转化率；内容表缺少成交归因时不宣称某视频贡献了某笔订单。

首版的“每日自动巡检”针对已导入的数据，页面必须展示数据截止时间。缺少当天所需数据时生成补数任务，不能声称已自动读取最新后台。导入数据与现有演示数据分开标识及统计。

## 3. 短视频运营

### 3.1 账号与数据

建立“业务店铺—平台账号”的关联，允许一家店绑定多个内容账号。单店/多店查询均继承现有授权检查。

按实际数据源支持的字段读取：发布时间、视频标识、标题、播放量、互动量、完播表现、涨粉、商品点击及可验证的成交。每项指标记录统计窗口、累计或当日增量、采集时间和来源。

区分平台授权同步、人工报表导入与演示数据；不把尚未接入的账号显示为已同步。没有权限或来源不提供的字段展示为“暂无数据”，不能补成零。

### 3.2 同行视频拆解

输入可以是用户提供的视频、字幕、转写或可实际读取的参考资料。只有链接且无法获取内容时，明确资料不足，不声称已经观看或完成视觉拆解。

拆解结果包含：

- 目标人群、使用场景、选题与核心卖点。
- 开头钩子、内容推进、证据表达、转化引导。
- 镜头、字幕、节奏与可复用的结构；有时间信息时附时间段。
- 可观察事实、效果假设、适合本店的改编方向。

公开互动数据不能替代同行后台完播或成交数据；后两者没有来源时不推断为事实。

### 3.3 文案与分镜

依据本店定位、真实商品资料、历史视频表现及同行拆解，生成选题、标题、封面文案、口播、分镜和素材清单。脚本支持版本化修改，并保留所引用的商品事实与数据快照。

输出必须能够继续进入剪辑：每段具备目标时长、画面要求、口播/字幕与对应素材。缺少素材、价格或活动资料时形成待补充项。

### 3.4 自动剪辑

首个可验收范围：用户提供可用素材，系统按脚本选择片段、裁切画面、拼接、添加字幕和指定音轨，生成可播放的竖屏成片及封面。

剪辑计划与渲染结果分开保存。任务展示排队、处理中、成功、失败；失败保留原因并允许重试，重复提交不生成重复任务。字幕时间轴和音轨缺失应有明确处理结果。

验收以实际导出文件为准，包括播放、画幅、音画同步、字幕可读性和素材对应关系。输出文案或剪辑建议不算自动剪辑完成。

语音、视频理解和剪辑执行需要各自的工具能力，现有文字模型调用不能被当作这些能力已经具备。自动发布是独立执行步骤，接入范围和授权方式另行明确。

### 3.5 效果回流

发布后记录平台视频标识，将视频、脚本版本、成片与后续数据关联。按同类内容和可比统计窗口复盘，提出下一轮实验，并关联到运营任务。

## 4. 抖店日常运营与每日工作

围绕商品销售与快递履约安排每日工作，覆盖商品、库存、待发货、物流、售后和内容计划；具体检查依赖实际导入的字段。

### 4.1 每日 SOP

按店铺配置巡检模板、执行时间、负责人和规则阈值。初始模板覆盖：

| 阶段 | 工作 | 产出 |
| --- | --- | --- |
| 开始工作 | 检查数据是否更新，回顾昨日经营、内容表现和未结问题 | 每店晨报、异常清单、当日优先事项 |
| 当日推进 | 检查商品状态、库存、待发货与物流、售后处理和内容计划 | 有负责人和截止时间的任务 |
| 工作中 | 回填进度、素材、处理结果与阻塞原因 | 任务记录和问题单 |
| 结束工作 | 汇总完成项、未完成项、新问题和次日安排 | 日报、遗留问题、次日计划 |
| 后续复盘 | 检查已执行动作对应的数据变化 | 效果记录与下一步实验 |

初始任务示例：补齐昨日缺失报表、核查销量异常商品、核实低库存、处理临近发货时限订单、跟进退款原因、完成当日视频。风险判断需要对应的库存、承诺发货时间或售后字段，资料不足时只生成核查任务。

### 4.2 任务和问题闭环

每个任务包含店铺、日期、类型、触发证据、优先级、负责人、截止时间、预期产出和状态。按“待处理 → 进行中 → 待验收 → 已完成”推进，另设阻塞、取消状态。

问题单记录所属任务、现象、数据证据、影响范围、负责人、处理过程、解决结果与复盘。日报自动聚合逾期、阻塞、反复出现的问题。

定时生成以店铺、业务日期和模板版本去重。已回填的任务不能被下次生成覆盖，修改规则后保留历史版本。

任务完成以回填和验收记录为依据；聊天中生成建议不等于业务工作已经执行。

## 5. 全店数据分析

“所有店铺”指当前账号授权的店铺，既支持总览，也支持逐店下钻。首页应能回答：哪家店出现什么变化、证据是什么、今天由谁采取什么动作。

| 维度 | 分析目标 | 所需来源 |
| --- | --- | --- |
| 经营 | 成交、订单、退款、客单价、商品/渠道贡献 | 现有订单分析可复用，真实数据另接入 |
| 短视频 | 内容表现、互动、关注和可验证的转化 | 对应账号数据与视频关联 |
| 商品与履约 | 商品表现、库存、待发货、物流及售后问题 | 实际可导出的商品、订单、库存和售后报表 |
| 执行 | SOP 完成率、逾期、问题解决时间、动作后表现 | 任务、问题、发布与数据记录 |

分析采用“事实 → 待验证原因 → 建议动作 → 跟进时间”。不能仅凭两条趋势宣称因果关系，也不能把未扣除成本的净收款当成利润。

统计遵循：

- 同一时区、时间窗口和业务口径下比较；默认沿用项目上海时区完整自然日。
- 跨店比率按分子与分母重新汇总，不平均各店百分比。
- 支付、发货、退款时间分别建模；期间退款与订单批次退款率分别表达。
- 平台与业务类型口径不同的指标分开呈现；没有订单归因依据时不把视频点击当成交贡献。
- 数据缺失、过期、重复与导入失败都进入数据质量报告，不生成正常经营结论。
- 指标和金额由确定性代码计算，模型负责解释与提出待验证假设。

## 6. 工作台与实现职责

运营登录后进入“今日工作”，主要入口为：今日工作、短视频运营、店铺运营、全店分析、问题与复盘、数据导入。选品作为运营工具保留。

沿用现有 Vue、FastAPI、PostgreSQL 和 Dify 结构：

- 前端展示任务、视频资产、分析证据、处理状态和实际产出。
- 业务 API 负责店铺授权、账号绑定、指标计算、任务状态和资产归属。
- Dify 承担有上下文的诊断、拆解、文案生成与复盘；每步结果进入明确的业务记录。
- 新增持久化调度和后台执行能力，负责报表处理、每日 SOP 与剪辑，后续扩展接口同步。刷新页面不能丢失任务。

新增数据对象至少包括平台账号、同步批次、指标快照、视频资料、拆解报告、脚本版本、素材、剪辑任务、SOP 模板、每日任务和问题记录。对象均携带店铺归属，外部账号/视频标识按平台命名空间去重。

单店执行任务固定具体店铺；多店报告保存生成时的授权范围与数据批次。执行或查看历史产出时重新检查授权，避免成员权限变化后仍可读取旧店铺资料。

## 7. 分阶段交付与验收

完整范围包含真实报表导入和自动剪辑，分阶段用于让每一步都可验证。平台 API 同步作为取得权限后的增强能力，不作为首版前提。

| 阶段 | 交付 | 验收场景 |
| --- | --- | --- |
| 第一阶段：运营工作闭环 | 数据导入规范、每日 SOP、任务跟进、问题记录、全店分析和日报 | 导入两店数据，生成独立任务，回填阻塞与完成项，日报准确汇总；重复生成无重复任务，跨店无越权 |
| 第二阶段：内容生产闭环 | 账号/视频资料、同行拆解、选题与脚本、版本化素材和剪辑成片 | 一份真实可读取的同行参考与一组本店素材，产出有依据的拆解、脚本和可播放成片；失败可查可重试 |
| 第三阶段：持续运营闭环 | 定时巡检、补数提醒、发布关联与效果回流 | 依据已导入数据生成诊断及任务，数据过期可见；次日导入新报表后可复盘；后续再扩展 API 同步 |

报表导入可以作为真实业务数据来源，但不能表述成自动读取账号。后续“自动读取真实账号”必须以实际同步记录验收，不能用演示数据代替。

## 8. 已确认范围与后续输入

1. 已确认：主要抖音；抖店商品销售、快递发货；当前没有接口，首版使用后台导出的报表。

3. 素材来源：现成商品视频、同行参考、口播音频或字幕；是否需要额外的配音能力。
